# Goal 175 — SSE2 bit-exactness: the named test does not cover it

Registry goal 175 says:

> make test_mir_float green: DADD/DMUL/DDIV/DGT results are bit-exact vs wubu_softfloat

## Measured

- `make test_mir_float` builds and reports **3/3 passed**.
- Its link line (`Makefile` ~145) is: `wubu_mir*.c`, `x86_peephole.c`,
  `wubu_softfloat.c`, `wubu_tgemm.c`, `tools/test_mir_float.c`.
  **No ISA backend is linked** — `wubu_isa_x86_64.c` is absent.
- `grep DADD|DMUL|DDIV|DGT tools/test_mir_float.c` returns **nothing**.
- The binary prints `=== 3/3 passed (MIR float interp) ===` and is dated Oct 15.

So the test exercises the MIR interpreter against softfloat, not the x86-64
encoder. Whatever it proves, it does not prove that `addsd`/`mulsd`/`divsd`/
`ucomisd` produce bit-identical results to `wubu_softfloat`.

## What a real check needs

Encode the four ops with the ISA backend and execute them, comparing 64-bit
results against `wubu_softfloat`:

1. compile a program per op via `wubu_isa_x86_64_compile` + `x86_run`,
2. call the same op through `wubu_softfloat`,
3. compare **bit patterns**, including NaN payload propagation and the sign of
   zero — `==` would let NaNs and ±0 through.

The driver already links the encoder and the interpreter, so this belongs in
`test_isa_driver` rather than in `test_mir_float`, whose link line cannot see the
backend without changing it.

Goal 175 stays open. Note that 124 (xmm0 return) is separate: 175 is about the
arithmetic encoding, which does run in xmm registers.
